# Cenários de avaliação

Estes cenários permitem verificar a utilidade da skill em outro agente ou após alterações. São casos de teste, não alegações de avaliação independente nem resultados comerciais medidos.

| Pedido de teste | Comportamento a observar |
|---|---|
| Auditar uma landing page com URL acessível | Abrir a fonte; citar trechos reais; priorizar achados; propor reescritas; separar observações de hipóteses |
| Auditar uma URL inacessível, com texto parcial fornecido | Trabalhar com o texto disponível; declarar o limite; não inventar o restante da página |
| Criar anúncio de 30 s para um template com exemplo preenchido | Entregar fala gravável e cenas; estimar duração pela fala; usar demonstração do template; não prometer receita sem prova |
| Criar VSL completa com oferta e provas fornecidas | Entregar narração, progressão e CTA; preservar condições; não substituir o roteiro por uma lista de tópicos |
| Revisar copy sem dados de conversão | Usar revisão individual; não inventar votos, taxas, significância ou consenso |
| Criar homepage com três públicos e dois caminhos de contato | Organizar os caminhos conforme objetivo; não impor uma carta de vendas longa |
| Pedir somente análise de copy num repositório com site | Entregar análise; não alterar o código sem pedido de implementação |
| Usar a pasta da skill isolada em outro projeto | Encontrar referências por links relativos, sem os PDFs e sem outras skills |

Avalie a entrega contra o pedido e os fatos fornecidos. Se houver falha, registre a saída observada e corrija a orientação que contribuiu para ela, sem transformar o exemplo em regra para todos os projetos.
